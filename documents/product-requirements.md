## 一、产品定位

### 1.1 一句话说清

**对着手机讲 2~5 分钟，AI 按你的模板整理成结构化复盘，自动落进你电脑上的 Obsidian 库。**

### 1.2 它不是什么

明确划清边界，避免功能蔓延：

- **不是**多用户产品 —— 没有注册、没有登录、没有账号体系
- **不是**云服务 —— 不做服务器、不做云端数据库、不做多设备实时同步
- **不是**笔记应用 —— 不做富文本、不做标签体系、不做双链、不做图谱
- **不是**团队工具 —— 不做协作、不做分享、不做评论

### 1.3 要解决的核心问题

| # | 问题 | 后果 |
| --- | --- | --- |
| 1 | **复盘坚持不下来的真正原因不是不会复盘，是懒得打字** | 打字成本高 → 三天热度 → 复盘库空空如也 |
| 2 | 口语内容是散点，没有结构化容器 | 就算记了，日后翻看也找不到重点 |
| 3 | 记在手机里的东西沉淀不到已有的知识库 | 复盘和 Obsidian 里其他笔记是两座孤岛 |
| 4 | 没有反馈，看不到自己复盘的坚持情况 | 缺少正反馈，进一步削弱坚持意愿 |

### 1.4 产品原则（高于具体功能）

1. **快**：从掏出手机到开始讲话，不超过 2 次点击。
2. **数据主权归自己**：默认全部存本机，不上传任何服务器（AI 整理环节除外，且仅发送文字）。
3. **不锁死**：产出物是标准 `.md` 文件，脱离本应用照样能读、能改、能带走。
4. **不假装聪明**：AI 只负责整理，不负责替用户思考、不添加用户没说过的内容。

## 二、目标用户与使用场景

### 2.1 用户画像

| 项 | 描述 |
| --- | --- |
| 人数 | 1 人（本人） |
| 设备 | Android 手机（主力）；Windows 电脑（查阅、归档） |
| 已有工具 | Obsidian 桌面版 + 手机版；DeepSeek API Key |
| 使用频率 | 每天约 1 次 |
| 技术水平 | 非常规用户。能装 APK、填 API Key、配一个同步盘，但不会调试、不会看日志 |
| 对工具的容忍度 | 低。操作超过 3 步、等待超过 1 分钟，就会放弃使用 |

### 2.2 核心场景（按重要度排序）

**场景 A — 记录（每天发生，最高频）**
> 下班路上或睡前，掏出手机，点一下麦克风就开始讲：今天做了什么、卡在哪、有什么感触、明天准备干什么。讲完点「整理」，AI 给出结构化的四栏内容，扫一眼改两个错别字，保存。全程 3 分钟以内。

**场景 B — 回顾（每周几次）**
> 想看看上周某个事当时是怎么想的，打开复盘库，按时间往下翻，或者直接搜关键词，点开看全文。

**场景 C — 沉淀（自动发生）**
> 在电脑上打开 Obsidian，复盘文件按年月自动排好，和别的笔记在同一个库里，可以直接引用、双链。

**场景 D — 回看长期（每月一两次）**
> 想知道这个月反复卡在哪些问题上，让 AI 把这一周的复盘汇总成一份小结。

**场景 E — 补录（偶发）**
> 某天没来得及说，第二天想用键盘补一段。**必须留手动输入的兜底路径。**

## 四、关键产品决策

| 决策项 | 结论 | 理由 | 备选方案与代价 |
| --- | --- | --- | --- |
| **输入方式** | 语音为主，键盘为辅 | 语音是降低复盘门槛的唯一手段；但必须留手动输入兜底，否则识别失败时会卡死流程 | 纯语音（失败即无法记录）—— 否决 |
| **语音识别方案** | 安卓系统自带识别 + **分段续录** | 零成本、零注册、无需引入第三方 SDK、语音数据不出本机 | 第三方（讯飞等）连续识别 180 分钟、准确率更高，代价：需注册、按量付费、安装包增大 30~50MB、语音上传第三方。**若实测准确率不可接受，再切换** |
| **AI 角色** | **纯整理器**，不追问、不加料 | 用户明确选择。可控、可预期，不会出现 AI 自作主张添加内容 | 对话式引导（AI 先反问）—— 体验更好但用户未选；整理质量、速度均更差 |
| **AI 服务商** | DeepSeek（用户已有 Key） | 接口兼容 OpenAI 格式、中文口语转书面语效果好、支持 JSON 输出模式、价格低 | 通义 / 智谱 —— 接口格式不同，换用需改代码 |
| **模板** | 完全自定义，栏目由用户提供 | 用户明确要求用自己的模板 | 内置多套框架可选 —— 用户未选 |
| **存储** | 本机为唯一数据源；可选镜像写入 Obsidian 库文件夹 | 隐私最好；`.md` 通用；换设备靠文件夹同步 | 云端账号同步 —— 需额外搭后端，方案变重 |
| **电脑联动** | 文件夹同步（坚果云 / Syncthing / OneDrive），**不做"导入"功能** | Obsidian 的"库"本质就是一个装 `.md` 的普通文件夹，两端共用同一批文件即可，导入是多余步骤 | Obsidian Local REST API 插件 —— 需同 WiFi，多一层依赖，列为备选 |
| **AI 整理时机** | 用户点「整理」才调用，不自动触发 | 避免用户还没说完就消耗额度；也便于用户先自行修正识别错误 | 转写完成即自动整理 —— 用户无法干预 |

## 五、非功能性需求

| 维度 | 要求 |
| --- | --- |
| **可用性** | 录音必须**离线可用**（未联网也能录、能保存），不为网络问题丢失内容 |
| **性能** | 应用冷启动到可点击录音 ≤ 2 秒；5 分钟口语的 AI 整理耗时 ≤ 30 秒（含等待提示） |
| **成本** | 单次复盘的 AI 调用费用 < 0.1 元 |
| **体积** | APK 体积目标 < 15 MB |
| **兼容性** | Android 8.0（API 26）及以上 |
| **数据安全** | API Key 仅存本机；全部复盘数据仅存本机；提供导出备份能力 |
| **容错** | 任何一步失败（识别失败、AI 超时、写入失败）都不得丢失已输入的文字 |
| **可维护性** | 关闭 AI 功能后，应用仍应能完成"录音 → 转写 → 手动填写 → 保存"全流程 |

## 六、风险与对策

| # | 风险 | 影响 | 对策 |
| --- | --- | --- | --- |
| 1 | 系统语音识别中文准确率约 82~85%，人名、专有名词、行业术语易错 | 返工修改成本高，久了会放弃 | ①转写结果实时可见，随说随改；②全部栏目可编辑；③P2 提供术语替换表；④实在不行切换第三方 ASR |
| 2 | 系统识别单次约 60 秒上限，长口述会被切断 | 一句话被切成碎片，语义断裂 | **分段续录**：临近上限时自动接续下一段，拼接处保留段落分隔；用户全程无感 |
| 3 | 不同手机厂商的识别引擎差异大，部分机型不支持或质量差 | 功能直接不可用 | 首次使用时做能力检测；不支持时自动降级为「键盘输入」模式，功能不受影响 |
| 4 | Android 11+ 分区存储限制，写入任意文件夹需授权 | Obsidian 联动失效 | 使用系统文件夹选择器由用户授权一次，授权长期有效 |
| 5 | 数据只在本机，手机丢失 / 损坏即全部丢失 | 数据损失不可接受 | ①可配置镜像写入 Obsidian 库文件夹（等于第二份）；②提供全量导出；③建议搭配同步盘 |
| 6 | AI 整理时产生幻觉，添加了用户没说的内容 | 复盘内容失真，是根本性错误 | 提示词强约束"只整理不添加"；界面标注「内容由 AI 整理，请核对」；提供「跳过 AI 手动填写」入口 |
| 7 | DeepSeek 接口超时 / 欠费 / Key 失效 | 流程中断 | 所有失败路径都不丢原文；提供"跳过 AI"按钮；错误信息用中文说明具体原因 |
| 8 | 目标用户技术水平有限，Key 配置、文件夹授权可能卡住 | 应用装上了但用不了 | 设置页给出逐步引导文字；提供"暂不配置，先用无 AI 模式"的路径 |
| 9 | 缺少反馈导致坚持不下去（产品的根本风险） | 产品失败 | 数据看板（连续天数、字数趋势）+ 周月汇总，制造正反馈 |

## 七、成功标准

自用产品不用 DAU 衡量，用这几条：

1. **能连续 7 天，每天完成一次复盘，且不觉得麻烦。** 这是最硬的一条。
2. 从解锁手机到开始讲话，**≤ 2 次点击**。
3. 语音转写后需要手工修改的比例**主观感受在可接受范围内**（否则触发第三方 ASR 的切换评估）。
4. 电脑端 Obsidian 里能直接看到当天复盘，**全程没有任何"导入"动作**。
5. 手机上的复盘文件与电脑上的文件是同一份，不存在"哪边是最新的"这种疑问。
